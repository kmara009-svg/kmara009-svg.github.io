# REFUEL. REBUILD. RETURN.

A presentation website for a RED-S rehabilitation pitch by **Kyle Marambio** (Sports Trainer & S&C Coach): a criteria-based recovery plan for Shantha, a 19-year-old national-team distance runner.

The content (every section, figure, table, number and APA reference) is taken verbatim from the `RED-S_Rehabilitation_Strategy.pptx` deck and lives in one file: `lib/content.ts`.

## Stack

Next.js (static export) · Tailwind CSS v4 · Framer Motion · GSAP. Real video footage and real radiographs, with no WebGL.

## Run it

```bash
npm install
npm run dev      # http://localhost:3000
npm run build    # static site in ./out
```

Pushing to `main` deploys to GitHub Pages through `.github/workflows/deploy.yml` (set the repository's Pages source to "GitHub Actions").

## Presenting (screen recording)

* Every stop is a 1920×1080 stage, scaled to fit the window. Record at 1920×1080 for a 1:1 layout.
* `→` `↓` `space` `enter` (or a wheel notch or swipe) move one stop forward; `←` `↑` go back; `Home` / `End` jump.
* Moving forward plays a short real clip (about 3 s), then the next slide fades in as the clip ends. Pressing again while a clip plays skips to its end, and never skips a slide. Moving back cuts straight to the previous stop.
* The story opens on an athlete warming up at dawn behind the titles. A run along the track turns into an X-ray: real radiographs of the pelvis (high risk), tibia and foot (lower risk) with the bones marked. The femur cross-section then loses its trabecular bone and rebuilds it, and she pushes off down the lane into the slides.
* Press `P` for presentation mode: fullscreen, cursor hidden, navigation chrome hidden. `Esc` leaves it.
* The top-right 600×400 px of every stop is kept free of text and graphics for a webcam overlay. Open `/?qa=1` to see that zone outlined, and `/?stop=N` to open on stop N.
* All text is 28 px or larger at 1920×1080, except the references, which shrink to fit on one slide.
* Clips are fetched in the background in presentation order, the next two first. Open the site a minute before presenting so everything is cached.

## Project map

| Path | What it is |
|---|---|
| `lib/content.ts` | All deck content, in deck order |
| `lib/deck.ts` | The stops (six story beats, then 21 slides), the clip each slide arrives with, and the store that moves between stops |
| `lib/media.ts` | Clip list with durations (generated by `scripts/encode-media.mjs`) |
| `lib/xray.ts` | Radiograph placement, bone markers and image credits |
| `components/Experience.tsx` | Stage scaling, keyboard / wheel / swipe input, presentation mode |
| `components/MediaLayer.tsx` | Full-screen footage: plays each move's clip, rests on its last frame, X-ray look for the anatomy beats |
| `components/story/` | Hero titles, radiographs, and the femur cross-section (2D canvas) |
| `components/sections/` | One component per slide |
| `components/charts/` | Risk bars, energy-availability zone bar, interval chart |
| `scripts/media-sources.json` | Each clip's source, licence page and trim points |
| `scripts/encode-media.mjs` | Downloads, trims and encodes the clips into `public/media/` |

The injury-report slide uses `public/images/injury-report.png`; swap that file to change the form image.

## Footage

Each clip is its own short file (H.264, 1920×1080 at the source's 24 fps, a keyframe every 0.5 s, no audio). Each one starts on its first frame, so playback never waits on a seek. Its first and last frames are saved as JPEGs: the last frame is what stays on screen behind a slide.

To change a clip, edit its trim points (`in`, `out`) or source in `scripts/media-sources.json` and run `node scripts/encode-media.mjs` (needs ffmpeg). The script rewrites `lib/media.ts`. To change which clip leads into which slide, edit `SLIDE_CLIPS` in `lib/deck.ts`.
